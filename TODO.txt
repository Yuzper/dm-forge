Good — that simplifies things. Dropping the player-facing/second-window ideas entirely (DM-only), and your Sessions tab is the live-run surface, so I won't build a competing "run mode." That leaves your three: global search, calendar, encounter builder. Here's how I'd scope each so we can sequence them.

Global search (command palette)
Cmd/Ctrl+K overlay; fuzzy-search across articles, sessions, relation webs, loot tables — and optionally run actions ("New NPC", "Open soundboard").
Reuses your existing setView/setCampaignSubView navigation and the data already in the store. No schema changes.
Smallest, self-contained, biggest daily payoff. ~1 sitting.

Encounter builder
Pick creatures (from your creature articles) → see XP total vs party difficulty thresholds (party size + level config), then push the encounter straight into the combat tracker.
Needs: a small party-config (level/size) somewhere, the 5e XP-budget + multiplier tables, and a builder UI. Hooks into combat/creatures you already have.
Medium. Mostly additive, one new config concept.
Needs a "Unaccounted for" list with creatures with no XP value. The config should be pr session since player amount can differ. Add a disclaimer something like "Remember the dice introduce randomness so an encounter might be more or less difficult than the expected classification."

Calendar system
Per-campaign calendar definition (months, days-per-month, weekdays, optional moons/festivals), a "current date" you advance during play, and recurring events that surface on the timeline.
Biggest because it touches the in-world date model, the timeline, and events — real data-model decisions (and a migration path for existing in-world dates).
Largest, most foundational. Worth doing carefully.
